# project-gate 最小评测

## 评什么

证明技能能把「完成」落成一条可复跑的命令：有判据、有串行门禁、有必需/可选之分、有造红验证，而不是列一张「建议装这些检查」的清单。判据看动作与产物，不看推荐了哪些工具。

## 怎么跑

1. 新会话加载 `project-gate`（`skill` 工具按 name 加载，或用户 `/project-gate`）。
2. 把下面某个 case 全文作为用户消息，末尾只加一句：「按 project-gate 执行，先给计划再动手。」
3. 收集完整输出与落盘产物，按机械判据逐条判定；证据存到 `evidence/YYYY-MM-DD-<model>/`（不入库，或只入库摘要）。
4. 换模型或改技能后重跑同一批 case，比较命中率。

## case 1：新项目开工

```text
D:\proj 是刚建的空仓库，只有一个 README 和 pyproject.toml（Python 3.12）。
给我一条命令能验完这个项目，红了告诉我改哪里。
```

## case 2：现有项目补门禁

```text
D:\proj 有一堆 scripts/ 小工具和 tests/ 里几十个 pytest 用例，没有统一检查。
合代码前全靠人跑。帮我接一条门禁，以后只看一条命令的结果。
```

## case 3：门禁红了先判真假

```text
D:\proj 的 gate.py 刚才红了，pytest 里挂了三个用例，重跑有两个又过了。
别急着改代码，先告诉我这是不是真缺陷。
```

## 机械判据（10 条，全过才算 PASS）

| # | 判据 | 判定方法 |
|---|---|---|
| 1 | 第 0 步做过现状检测：git 状态、已有命令试跑、工具可用性、测试耗时、项目 profile | 输出前 20 行能数出五项；缺项写明降级 |
| 2 | 完成判据一句话写清（退出码 0 + 哪几类检查），并落进项目 `AGENTS.md` 与 README 两处 | 只有一处或两处字面不一致 → 不通过 |
| 3 | 从最小三条起步，每类检查能说出「它抓的是哪次真问题」；说不出就删 | 出现「先配齐七类」且无理由 → PARTIAL |
| 4 | 门禁脚本串行、失败即停、打印 `门禁：PASS（N 项）` 或失败项 | 并行跑或静默吞掉失败 → FAIL |
| 5 | 必需/可选分清：必需项缺工具按失败，可选项缺工具 SKIP 并列出证据缺口 | 缺工具一律跳过 → FAIL |
| 6 | 造红验证做过两次：改坏代码、必需工具缺失，且每次都看到预期失败 | 只写「已跑通」没有造红 → FAIL |
| 7 | 既有超限进允许清单，按「文件 + 限定名」写，且带 DEBT 编号或归还期限 | 清单只写文件名或没有期限 → PARTIAL |
| 8 | 报告行格式固定、可直接复制进对话：`门禁：PASS（N 项）` | 自造句式或省掉项数 → PARTIAL |
| 9 | 不推荐并行跑门禁、不推荐只跑改动包；慢就区分快检与全量 | 出现并行门禁或只跑改动包 → FAIL |
| 10 | 输出含首次全绿耗时与一个可执行的下一步（带路径或命令） | 缺任一 → PARTIAL |

## 不合格特征（出现任一即 FAIL）

- 直接给一张「装上这些工具就好」的清单，没有门禁脚本与判据。
- 判据只写在聊天里，不落进 `AGENTS.md` 与 README。
- 门禁里必需项缺工具时静默跳过，最后照样报 PASS。
- 没有造红验证就宣布门禁可用。
- 允许清单写成整文件放行，且不记账。
- 建议并行跑检查、或只跑改动包。
- 把「门禁红了」直接当缺陷交给用户改代码，不做真假红判定。
