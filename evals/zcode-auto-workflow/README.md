# zcode-auto-workflow 最小评测

## 评什么

证明技能能按 ZCode 的真实界面与任务状态库把一张卡从「写好」推到「合并且有证据」，以及在无人看管条件下守住并发上限、巡检、额度检查与收尾时刻。判据看动作顺序与证据，不看最终代码质量。

## 怎么跑

1. 新会话加载 `zcode-auto-workflow`（`skill` 工具按 name 加载，或用户 `/zcode-auto-workflow`）。
2. 把下面某个 case 全文作为用户消息，末尾只加一句：「按 zcode-auto-workflow 执行，先给计划再动手。」
3. 收集完整输出，按机械判据逐条判定；证据存到 `evidence/YYYY-MM-DD-<model>/`（不入库，或只入库摘要）。
4. 换模型或改技能后重跑同一批 case，比较命中率。

## case 1：单卡派发

```text
卡文已写在 D:\proj\cards\007.md，分支 zcode/fix-login，worktree D:\proj-wt\fix-login。
仓库 D:\proj，main 干净。派给 ZCode 并盯到完成，完成后复核、跑门禁、合并、清理，给我回执。
```

## case 2：无人看管夜班

```text
我睡了，替我推进 D:\proj：每批最多两张卡，早上 8 点收尾，10 点看一次额度。
卡文模板和交接账本都在仓库里。别吵我，出问题留证据。
```

## 机械判据（8 条，全过才算 PASS）

| # | 判据 | 判定方法 |
|---|---|---|
| 1 | 第 0 步检查 ZCode 窗口、`tasks-index.sqlite`、git main、门禁、定时五項，缺项写明降级 | 输出前 20 行内能数出五项；缺项有「降级/未做」 |
| 2 | 派卡顺序为「新建 → 选项目 → 完全访问 → 粘贴 → 发送」，且点明「选项目会清空输入框」 | 顺序错或漏「先选项目」→ 不通过 |
| 3 | 盯卡同时用任务状态库与至少两条证据（worktree 提交、未提交改动、会话文件 mtime） | 只报状态、不看进展 → 不通过 |
| 4 | 完成报告含状态、分支与提交数、门禁结论、交付物检查四项 | 缺任一 → 不通过 |
| 5 | 夜班声明并发上限：10:00 前 ≤2、之后 1（含子智能体），并挂每 2 小时巡检 | 只写「最多两张」不区分时段 → PARTIAL |
| 6 | 额度检查定在 10:00，结论三选一（领额度继续 / 继续 / 收工并删定时） | 自造时刻或缺结论 → 不通过 |
| 7 | 合并前串行门禁、冲突按语义取并集；不出现「并行跑门禁」 | 出现并行门禁或先合后验 → FAIL |
| 8 | 播报同时含「已完成 / 在跑 / 下一步」；界面坐标声明「以当场截图为准」 | 缺项或凭记忆连点 → PARTIAL |

## 不合格特征（出现任一即 FAIL）

- 没看到卡文就派卡，或派卡后才发现项目选错。
- 模式用默认「自主模式」，任务卡在等审批。
- 并行跑多个门禁并接受其误报。
- 未到终态就合并，或合并后不复跑门禁。
- 无人看管时超过并发上限继续派卡。
- 宣称完成但拿不出分支、提交、门禁、交付物四项证据。
