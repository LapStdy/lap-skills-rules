# first-principles 最小评测

## 评什么

证明技能产出的是「一页可拍板的决策备忘」，而不是「一份优化建议清单」。判据看方法步骤是否到位，不看推荐结论是否与参考一致——不同的目标函数可以推出不同的最优解。

## 怎么跑

1. 新会话加载 `first-principles` 技能（`skill` 工具按 name 加载，或用户 `/first-principles`）。
2. 把 `cases/` 下某个 case 文件全文作为用户消息，末尾只加一句：「按 first-principles 评估，给结论。」
3. 收集完整输出，按下面的 rubric 逐条判定；把输出与判定结果存到 `evidence/YYYY-MM-DD-<model>/`（不入库，或只入库摘要）。
4. 换模型或改技能后重跑同一批 case，比较命中率；只比较同一 case 的判据通过数。

## 机械判据（8 条，全过才算 PASS）

| # | 判据 | 判定方法 |
|---|---|---|
| 1 | 入口 A/B 标出，决策问题一句话 | 输出前 15 行内能定位 |
| 2 | 目标函数含「谁 + 场景 + 时间 + 可观测结果」，不是方案形态复述 | 逐项对照；出现「做一个平台/系统」且无场景与结果 → 不通过 |
| 3 | 必要条件 3–6 条，每条可观测、可否定 | 每条能回答「怎么算不满足」 |
| 4 | 事实/假设/推断三栏齐全；事实有定位，假设有失效后果，推断有失效条件 | 抽查三栏各 ≥1 行 |
| 5 | 至少 1 条假设被推翻或标存疑，并点名受影响范围 | 找「假设 → 事实 → 受影响模块/阶段/成本」 |
| 6 | 候选 ≥3、覆盖 ≥4 类透镜，每条写「删什么」，至少一条换集成方式或换顺序 | 对照候选表；只加不减 → 不通过 |
| 7 | 每个候选过硬约束闸 + 四维评分 + 翻转条件；第一名有预登记判据与时间盒的最小验证 | 缺任一维 → 不通过 |
| 8 | 输出 ≤120 行、一页；决策点 ≤3 个互斥选项 + 一句推荐；未复述被评估方案 | 统计行数与选项数 |

## 不合格特征（出现任一即 FAIL）

- 跳过目标函数，直接从现有模块给优化清单。
- 把方案文档或用户自述当事实，不标证据等级与定位。
- 只给一个方案，或只靠「砍功能」得出更优解。
- 推荐没有最小验证，直接要求全面重构。
- 输出原理长文或百科式对照，没有决策点。
