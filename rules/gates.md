# 门禁与完成判据

> 一句话：完成由一条命令判定，不由感觉判定；门禁串行全绿才算完成。

## 它挡住什么

| 失败方式 | 后果 |
|---|---|
| 改完只跑相关测试就宣布完成 | 改动连带影响漏网，合并后才发现 |
| 门禁拆并行、只跑改动包 | 互抢全局资源产生假红；连带影响无人覆盖 |
| 门禁红了先改产品代码 | 掩盖环境性假红，真缺陷被顺手改坏 |
| 没有门禁的项目靠口头验收 | 每条规则退化成「记得就好」 |

## 完成定义

完成 ＝ 项目门禁一条命令退出码 0，且报告里写明哪几类检查全绿。

- 项目根固定入口 `scripts/gate.py`：`python scripts/gate.py`。
- 门禁内部串行，一条失败即停，输出「哪条、为什么、改法」。
- 交付前另跑交付物检查，回复正文报一行 `交付物检查：PASS（N 个文件）`。
- 命令同时写进项目 `AGENTS.md` 与 `README`，换项目只改这两处。

## 七类检查（按依赖顺序）

| # | 检查 | 典型工具 | 抓什么 |
|---|---|---|---|
| 1 | 格式与静态检查 | ruff、eslint、gofmt | 风格与低级错误 |
| 2 | 类型 | mypy --strict、tsc | 类型逃逸 |
| 3 | 测试 | pytest、vitest | 行为回归 |
| 4 | 依赖方向 | import-linter、AST 契约测试 | 分层被破坏、循环依赖 |
| 5 | 契约同步 | 状态机表、事件表、错误码表的驱动测试 | 文档与代码漂移 |
| 6 | 结构上限 | `tools/check_structure.py` | 模块、类、函数膨胀 |
| 7 | 交付物文字 | `tools/check_artifacts.py` | 历史渗入与施工字 |

小项目起步只要 1、3、7；每多一类，都对应真出过的那类问题。门禁按「够用」配，不按「齐全」配。

## 合并判据

1. 分支上跑一次全量：退出码 0 是合并前唯一证据。
2. 合并后按树判据决定是否再跑：`git diff --stat <分支头> <merge 提交>` 为空 ⇒ 内容逐字节相同，跳过并在回执写明理由；非空 ⇒ 必须跑完整门禁。
3. 不靠「只跑 pytest」省时间：格式与类型通常只占几秒，测试占大头；省时间的正确位置在「跑几次」，不在「跑几条」。

## 假红判据

| 现象 | 疑似原因 | 处置 |
|---|---|---|
| 单条用例红、其它全绿 | 并行抢全局互斥量、固定端口、共享数据目录 | 单例复跑 3 次通过 + 整包复跑全绿 ⇒ 判假红，记录后继续，不改产品代码 |
| 只在高负载机器红 | 时序断言（等固定毫秒、断言瞬时状态） | 改断言（见 `testing.md`），不加重试掩盖 |
| 资源类断言偶发多一条 | 磁盘水位触发额外事件 | 断言集合或下界，不断言精确条数 |

判别顺序固定：先复现（能复现才算真缺陷），再定位，最后改代码。不可复现的红写进 `DEBT.md` 并给归还期限。

## 门禁工程的三条经验

- 门禁自己也要被测：临时改坏一行，确认退出码 1，再撤销。
- 输出必须能照着改：失败行给文件与行号、期望、实际。
- 全量耗时写进 README；超过 5 分钟可拆「快检」与「全量」，但合并判据仍用全量。

## 检查清单

- [ ] 项目根有 `scripts/gate.py`，一条命令跑完全部检查
- [ ] 检查串行、失败即停、给可执行的改法
- [ ] 命令写进 `AGENTS.md` 与 `README`
- [ ] 合并前跑过一次全量，结论进回执
- [ ] 合并后按树判据决定是否再跑，理由写清
- [ ] 红过一次能说清是真缺陷还是假红，判据可复核
- [ ] 门禁自己造红验证过一次
