# 账本与欠账

> 一句话：做过的事进提交说明；没做的事进 TASKS；绕行与欠账进 DEBT 并带归还期限；跨会话续命靠交接账本。

## 四个账本，各管一段

| 账本 | 位置 | 放什么 | 不放什么 |
|---|---|---|---|
| 提交说明 / CHANGELOG | 版本库 | 做过的事与变化本身 | 待办 |
| `TASKS.md` | 项目根 | 还没做的事：能力、验证、口径 | 已完成项（做完即删） |
| `DEBT.md` | 项目根 | 绕行、欠测试、欠重构、手工步骤 | 正常待办 |
| 交接账本 | 仓库外 `handoff/` | 跨会话的当前状态与下一步 | 长期规则 |

## DEBT 规则

- 编号 `D-001` 递增，不复用、不跳号。
- 每笔写齐：日期、一句话债务（带文件或模块）、原因、影响、归还期限、状态。
- 归还期限写具体日期或版本号；写不出期限的当场决定做或不做，不入账。
- 同时未还 ≤20 笔；写满先还债，再加功能。
- 已还的条目直接删除，还债内容进提交说明与 CHANGELOG；台账只回答「现在还欠什么」，不留历史行。
- 绕过门禁的紧急修复必须记一笔，写清绕过了哪几条；补齐后删除。
- 每月复审一次；逾期项单列，写顺延理由与新期限。

## TASKS 规则

- 只记还没做的事；做完的删掉，删掉的动作由提交说明承载。
- 一条任务 = 一个可验收的结果；需要时给入口（文件、命令、复现步骤）。
- 被阻断的任务写清：阻断现象、复现命令、修复入口，让下一个人不必从头排查。

## 交接账本（跨会话唯一记忆）

四段固定顺序，缺段不算账本：

1. 任务状态
2. 目标
3. 已试方案与失败原因
4. 进度与下一步

硬约束：

- 每段 ≤5 行；失败项写成「方案 → 失败原因」，保留关键报错词。
- 下一步必须是可直接执行的第一步：带文件路径或命令。
- 写时机：每完成一张卡、方向变化、尝试失败、会话收尾。
- 账本只写动态状态；长期规则进 `rules/` 与项目 `AGENTS.md`。
