# 交付物通道规范

> 一句话：交付物只回答「此刻为真」。过程与历史走别的通道。

## 交付物是什么

文档正文、界面文案、代码注释。三者的共同点：读者是第一次看、没参与施工。

## 判据

> 删掉这句话，最终读者会不会少知道一件「此刻为真」的事？
> 不会 → 它不属于这里。

## 四条通道

| 通道 | 给谁看 | 寿命 | 放什么 |
|---|---|---|---|
| 聊天 | 用户本人 | 当天作废 | 解释、对比、前后变化 |
| 版本历史 | 维护者 | 长命 | 变化本身（提交说明、PR、CHANGELOG） |
| 草稿 / 任务清单 | 自己 | 短命 | 待办、草稿、下一步 |
| 交付物 | 最终读者 | 长命 | 现在是什么 |

臃肿不是字多，是通道混了。

## 五类症状与改法

| 症状 | 典型字样 | 改法 |
|---|---|---|
| 历史渗入 | 「之前」「原先」「已改为」「本次修改」 | 删掉，改写现状 |
| 施工字 | 「待定」「此处」「占位」「TODO」 | 写完再发；没内容就删整段 |
| 私人字条 | 「记一下」「回头再改」「先放着」 | 移到任务清单或交接账本 |
| 聊天腔 | 「刚才」「你说过」「接下来我」 | 改成第三人称的现状陈述 |
| 注释讲改动 | 「改成 X」「原来会崩」 | 只留为什么，变化交给版本历史 |

## 界面文案

读者是没参与施工的陌生人。界面里不许出现施工字、内部代号、「占位」说明。
「这里显示标题」「暂无数据（待接口）」是施工告示，不是文案。

## 代码注释

只写「为什么」：代码本身已经说明是什么，版本历史说明改了什么。

## 豁免

CHANGELOG、交接账本、`archive/`、迁移说明、测试冻结证据——它们本来就记历史。

## 检查

```bash
python tools/check_artifacts.py <目录>
```

- `PASS` + 退出码 0 = 干净。
- `WARN` + 退出码 0 = 只有中/低风险，不阻断，但交付前要清零；纳入门禁时加 `--strict`。
- `FAIL` + 退出码 1 = 有高风险，必须改。
- 规则抓词不抓意思：会误报也会漏报，它是兜底，不替代判断。
- 真误报：该行加 `artifact-check: ignore`。

## 为什么不做成技能

技能按触发词加载，不能保证每次写文件都生效。所以：硬规则放项目根的 `AGENTS.md`（常驻），全文放本仓库，机器检查交给检查器。
