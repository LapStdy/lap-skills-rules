# 测试可重复性

> 一句话：测试只依赖它自己造的世界；真实互斥量、固定端口、墙钟、外部进程都不属于测试。

## 它挡住什么

| 症状 | 根因 | 结果 |
|---|---|---|
| 门禁间歇红、重跑就绿 | 测试碰了共享资源 | 假红掩盖真缺陷，判红成本高 |
| 只在某台机器或某个时段红 | 依赖机器状态、时钟、磁盘水位 | 「完成」无法判定 |
| 断言精确条数或字节相等 | 上游多写一条事件、时间跨秒 | 无关改动把测试染红 |
| 修 bug 没加用例 | 没有失败证据 | 下次复发 |

## 四条硬规则

1. **外部依赖一律假件注入**：全局互斥量、固定端口、系统时钟、外部命令都换成可注入的假件；测试里不碰真实资源。
2. **断言不变量，不断言瞬时态**：异步派发后断言「恰好一条事件」「不早于某时刻」「最终状态属于集合」；不把时序当作契约去断言某个中间状态。
3. **不逐字节比对含时间的产物**：zip、日志、快照都比语义（条目集合、字段、结构）；确需比字节时先规范化时间字段。
4. **新行为必须有测试**：修 bug 先写能红的用例；写不出反例的修复不算完成。

## 进程、端口与文件

- 每用例独立临时目录；不共享可变全局状态，不依赖执行顺序。
- 需要真实进程时：子进程 + 独立控制台或独立进程组 + 端口取 0 由内核分配 + 超时；收尾用 `Popen.kill()` 与 `wait(timeout)`。Windows 细节见 `windows-process.md`。
- 服务地址、存储路径、时钟都从注入的配置取，不从进程级全局读。
- 文件写入用临时文件加原子替换；断言内容，不断言 inode 与 mtime。

## 时间

- 业务代码等待走注入时钟；测试用虚拟时钟推进，不用 `sleep` 等结果。
- 真实等待只用于等外部进程退出，且带超时与轮询上限；轮询间隔 ≥50 ms，不忙等。
- 时间断言用「差值不超过 X」，不写「等于 X 毫秒」。

## 文档即契约

- 状态机、事件表、错误码表放 `docs/`，由测试解析表格驱动断言；改代码或改文档任一侧漂移即红。
- 表格解析失败要报「哪个文件哪一行」，不静默跳过；解析不出表格按红处理。

## 检查清单

- [ ] 每个用例能单独跑、重复跑、并行跑
- [ ] 没有真实互斥量、固定端口、外部命令、系统时钟依赖
- [ ] 时序断言只断言不变量，不断言瞬时状态
- [ ] 没有逐字节比对含时间字段的产物
- [ ] 新行为有测试；修 bug 的用例修复前是红的
- [ ] 表格驱动的契约测试覆盖改到的表
