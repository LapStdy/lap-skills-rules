# AGENTS.md · <项目名>

本文件每次会话自动加载。项目背景见 README。

## 交付物通道（硬规则）

交付物 ＝ 文档正文、界面文案、代码注释。它只回答「此刻为真」。

1. 只写「现在是什么」；「原来是什么」「改了什么」「下一步做什么」进聊天、提交说明、任务清单，不进文件。
2. 改 ＝ 整段替换，不是追加。允许删旧版；不允许在旧句后面补一句新的。
3. 界面文案给没参与施工的陌生人看：不许出现「占位」「待定」「此处」「TODO」这类施工字。
4. 代码注释只写「为什么」，不写「改了什么」；改了什么由版本历史回答。
5. 本来就记历史的东西豁免：CHANGELOG、交接账本、archive/、迁移说明、测试冻结证据。

规矩全文与检查器：GitHub `LapStdy/lap-skills-rules` 的 `rules/` 与 `tools/`；本文件是操作版，两者冲突以仓库为准。

## 改动范围（硬规则）

改动范围 ＝ 本次请求要求改的文件与行。

1. 不动无关代码：不顺手调格式、改命名、补类型、换写法；不重构没坏的东西。
2. 只清自己造成的孤儿：自己改动弄成没人用的导入、变量、函数一起清；没碰过的死代码不删，记进 `TASKS.md` 或 `DEBT.md`。
3. 不混入独立工作：拆分、抽取、升级依赖、修无关红灯另开一张卡。

范围判据与收件箱：GitHub `LapStdy/lap-skills-rules` 的 `rules/change-scope.md`。

## 资产仓与技能

- 规范与技能的唯一源是 GitHub `LapStdy/lap-skills-rules`；本机技能装在 `~/.dsh/skills/`，从仓库安装，不手工改安装副本。
- 写技能、安装技能或调整项目结构前，先读仓库 `rules/skills.md` 与 `rules/project-structure.md`。

## 收尾自检（每次交付文件后、回复之前）

```bash
python scripts/check_artifacts.py .
```

1. 退出码 0 且输出 PASS 才算过；1 就按输出的「为什么 / 改法」改，改不动当场问。WARN（只有中/低风险）不阻断，但交付前同样要清零。
2. 在回复正文报一行：`交付物检查：PASS（N 个文件）` 或 `交付物检查：FAIL（高 N，已处理 / 待决定）`。
3. 确属误报：该行加 `artifact-check: ignore`；只用于真误报，不要拿它绕规则。
