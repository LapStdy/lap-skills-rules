# ZCode 自动工作流

一句话：一卡一 worktree，**事件驱动**盯卡，**门禁**是唯一的合并判据；无人值守时状态全落磁盘，会话可丢弃。

默认产出：派卡回执、盯卡结论、收尾账本。

## 何时用 / 何时不用

| 用户意图 | 去哪 |
|---|---|
| 「派卡」「发任务卡」「一次派两张卡」「复核后合并」 | 本技能 · 单卡模式 |
| 「盯 ZCode 到早上」「无人值守」「夜间自动推进」「到点收尾」 | 本技能 · 值守模式 |
| 「接续」「换个会话接着盯」「上下文满了」 | 本技能 · 接续流程（见「上下文与接续」） |
| 只写代码、跑测试、Git 操作，不涉及 ZCode 界面 | 直接用相应工具 |
| 想和 ZCode 无关地开一段新对话 | 直接开 DSH 新会话 |
| 需要用户在场拍板（真机观察、方向取舍、界面验收） | 停手，等用户醒 |
| 目标执行者不是 ZCode | 用 `subagent` 或 Agent Teams，不用本技能 |

判据：动作落在 ZCode 界面上，或要按任务卡循环推进的。单卡模式只走主流程一次并出回执。

## 输入与缺省

| 项 | 缺省 | 缺了怎么办 |
|---|---|---|
| 卡文 | 无 | 按 `references/card-template.md` 写；没卡文不派卡 |
| 项目常量 | `references/project-profile.md` | 换项目先改这一份 |
| 并发卡片数 | 2 | 含这些任务开出的子智能体 |
| 执行者模型与思考强度 | 见 profile | **以真源库为准**，不看界面芯片 |
| 额度窗口 | 见 profile | 窗口外不派新卡 |
| 收尾时刻 | 用户指定 | 没指定就取额度窗口结束时刻 |
| 门禁命令 | profile 里那条 | 没有就问用户 |
| 回执目录 | profile 里那条 | 没有就问用户 |

## 第 0 步：环境与真源检测

一条一条过，缺哪条就写明「降级/未做」与少了什么证据：

1. ZCode 进程在跑、窗口可见；侧栏「任务列表」折叠在项目行下时，先点项目行展开。「新建任务 / 任务列表 / 项目」属 ZCode，「新会话 / 工作区 / 会话」属 DSH，两套侧栏不要混点。
2. **真源库**可读：`%USERPROFILE%\.zcode\cli\db\db.sqlite` —— 权限、模型、思考强度都从这里读。
3. 仓库干净、记下 `main` 短哈希；`git worktree list` 确认没有残留或同名分支。
4. 门禁命令可跑：`main` 自上次全绿后动过、或没有近期绿色证据时跑一次全量；否则跳过（判据见「门禁跑几次」）。红了先排除环境性误报（见「门禁假红」）。
5. 唤醒通道可用：后台作业能起。

界面与真源的判据差异见 `references/boundary-facts.md`——那是实测踩出来的，不要凭界面显示下结论。

## 主流程（6 步）

1. **写卡**：按 `references/card-template.md` 写七段，再逐条过九项必查——定位、停手、现状可验收、现状→测试映射、竞争与错误语义、文档引用点、边界、预算与审查、首行与唯一码。判据：七段齐全且九项全过，缺一不派卡；卡文第一行只有 `卡<N>-<码>`，名称从第二行开始。
2. **派卡**：新建任务 → 选项目 → 确认完全访问 → 改模型与思考强度 → 粘卡文 → 回车。判据：**真源库**里 `session.permission` 为 `{"mode":"yolo"}`、`model_usage` 的 `model_id` 与 `variant` 符合 profile；任务标题等于卡文首行 `卡<N>-<码>`。
3. **盯卡**：起只读 watcher 后台作业（见「唤醒」）。判据：作业在跑，且能报出任务标题（含 `卡<N>-<码>`）与状态。用码对窗口：截图里标题栏只显示首行，码是唯一可靠的核对依据。
4. **复核**：读回执 `<回执目录>\HANDOFF-card<N>-<码>.md`（缺回执按未完成处理），逐分支看 diff，查三条红线——交付物只写「此刻为真」、无调试残留与死代码、新行为有测试。判据：回执字段齐全；每条红线给出「过 / 不过 + 文件与行」。
5. **合并**：`git rebase <main>` → 分支上跑全量门禁 → `git merge --no-ff` → 按「门禁跑几次」判据决定是否再跑 → 删 worktree 与分支。判据：该跑的都退出码 0、合并后工作区干净，并在回执里写明第二次门禁跑了没跑与理由。
6. **记账**：写交接账本四段式（任务状态 / 目标 / 已试方案与失败原因 / 进度与下一步），并记下回执路径与码。判据：下一步是可执行的第一步，带路径或命令。

## 唤醒：事件优先，时间兜底

**默认路径是事件**：起一个只读 watcher 后台作业，满足任一条件即退出，作业结束把本会话叫醒。等待期零 token。

watcher 四条退出条件（先到先退，缺一不可）：

| 条件 | 覆盖 |
|---|---|
| 运行态转终态（`completed` / `error` / `interrupted`） | 正常完成或失败 |
| 运行中但超过阈值无新提交、会话文件不更新 | 疑似卡死 |
| 出现等审批 / 等输入类状态 | 阻塞 |
| 超过兜底时长仍无变化 | 活性担保 |

**定时只用于两种情况**：到点收尾（时间是判据本身）、watcher 起不来时的降级。**不要用固定周期采样执行者**——事件密度不均匀，定时必然不是过密就是过疏。

判据：一夜结束后统计，若「无事可做的定时唤醒」超过 2 次，说明该定时本该删掉。

**watcher 的致命盲区**：基线快照里已经是终态的任务，永远不会再触发。所以启动 watcher 前必须先看一次当前状态；**若已无在跑任务，立即结束本回合去处理，不要启动 watcher**。

## 并发与变更预算

- 并发上限按 profile（默认 2，含子智能体）；到上限就等终态再派。
- **变更预算**：产品代码 ≤400 行；测试与文档按验收需要，不设固定上限，但交付说明里必须报出规模（「产品代码 X 行 / 测试 Y 行 / 文档 Z 行」）。
- 额度窗口外不派新卡：先等在跑的到终态。

## 门禁跑几次：按证据，不按次数

一次全量门禁约 210–230 秒，其中 pytest（约 1400 用例）占 95%，前六条合计约 5 秒。跑几次只看证据，不看习惯：

| 时机 | 规则 | 判据 |
|---|---|---|
| 分支上（合并前） | **必须跑一次全量**，这是合并前唯一的证据 | 退出码 0 |
| 合并后 | 只有 `git diff --stat <分支头> <merge 提交>` 非空才跑——主区在卡期间前进过、解冲突改过内容 | 树相同则不跑，回执写明「树相同，跳过第二次门禁」 |
| 派卡前 | `main` 自上次全绿后没动就不跑 | 动过或没有近期绿色证据才跑 |

规则：

- 树相同 = 合并提交的内容与分支头逐字节一致 = 前面那次全量就是同一份证据，重跑不新增信息。
- 树不同必须跑，且要跑完整七条；不为省时间只跑 pytest。
- 不为了省时间把门禁拆并行或只跑改动包——串行全量是抓连带影响的唯一关卡。
- 判据写成回执里的一行结论，别让用户猜这次跑没跑。

## 门禁假红

主区跑门禁时，执行者可能同时在跑测试，抢全局资源造成假红。判别与处置：

- 单条失败用例单独跑 → 通过；整包复跑 → 通过 ⇒ **判定为并行抢资源**，记录后继续合并，不改产品代码。
- 只有可复现的失败才算真缺陷。

## 上下文与接续

- 优先保证 watcher 在场；接续只是兜底，不是主路。实测单夜水位常从 25% 涨到 33%，多数整夜根本不需要接续。
- 接续 ＝ 换掉 **DSH 主控会话**（DSH 侧栏「新会话」），不是 ZCode 里点「新建任务」——后者只会多一张没人看的空卡。两条流程的点法、判据与误点后果见 `references/session-handoff.md` 第一张表。
- 换会话前先落盘账本，再开 DSH 新会话，标题按 `接续#<序号> · <项目> · <日期>`。
- 新会话**必须重建**：watcher 作业、收尾定时，并确认「main 位置、在跑卡、未合分支、下一步」四项——定时与作业都是会话级的，不会跟过去。

## 输出模板（缺项不算完成）

派卡回执：

```
已派：<卡名> / <分支> / <worktree>
码：<卡<N>-<码>>
模式：完全访问 / 模型 <模型> / 思考强度 <档位>（真源库核对结果）
卡文：<卡文路径>
回执：<回执目录>\HANDOFF-card<N>-<码>.md
唤醒：<作业号 / 四条退出条件 / 兜底时长>
```

盯卡结论：

```
状态：<运行中 / 完成 / 失败>
分支：<分支名> <提交数>
回执：<路径 / 未生成>
报告要点：<门禁结论 / 交付物检查 / 待办>
```

收尾账本：

```
任务状态：<main 位置 / 已合并卡 / 在跑卡 / worktree 状态 / 定时状态>
目标：<本夜目标与是否达成>
已试方案与失败原因：<踩过的坑与处置>
进度与下一步：<下一步可执行的第一件事>
```

## 停止规则与反合理化

| 借口 | 驳回 |
|---|---|
| 「坐标我记着，直接点」 | 一次取一帧，坐标会漂 |
| 「全屏截图更快」 | 全屏帧是缩放图，估读坐标偏二十像素以上；一律用窗口帧 |
| 「界面显示完全访问了」 | 界面显示不等于生效，去真源库读 `session.permission` |
| 「思考强度默认就是最高」 | 默认常是次高档；往返切一次再核对 |
| 「状态库的 mode 列写着 yolo」 | 运行中任务的 mode 列恒为 default，不作判据 |
| 「定时两小时巡一次最稳」 | 事件密度不均匀，默认事件驱动，定时只留给时间判据 |
| 「先合并，门禁回头再跑」 | 合并在门禁之后，顺序不可换 |
| 「冲突很小，整段用他们的」 | 冲突按语义取并集，覆盖等于丢改动 |
| 「跑了一次就挂 watcher」 | 先看当前状态；已无在跑任务就直接处理，别挂在空上 |
| 「门禁红了就是代码有问题」 | 单例与复跑都过 ⇒ 并行抢资源，不是缺陷 |
| 「『新建任务』和『新会话』差不多，随便点一个」 | 卡在 ZCode、会话在 DSH；点错不报错，只会得到空任务或空上下文 |
| 「接续就在 ZCode 里开个新任务」 | ZCode 没有主控会话；接续只能在 DSH 侧栏「新会话」 |
| 「合并后跑不跑看心情」 | 判据是树：`git diff --stat <分支头> <merge>` 空则不必跑，非空必须跑完整七条 |
| 「上下文还够，不写账本」 | 账本是跨会话唯一记忆，每步都写 |
| 「卡文写得像设计文档，够清楚了吧」 | 设计文档不等于可派卡；七段缺一、九项必查有一不过，就不派 |
| 「执行者会自己补测试和文档」 | 现状没有测试映射等于没有验收；DEBT 不销、docs 不写，账烂在原地 |
| 「先派下去，边跑边改卡」 | 卡文是工序书；要改就停卡重派，不追着改 |
| 「这套要求只对复杂卡生效」 | 九项必查对小卡也一样；小卡少的是条目，不是段和判据 |
| 「标题写得越全越清楚」 | 执行者把第一行当会话标题；长标题在窗口标题栏被截断，图像识别按 `卡<N>-<码>` 对窗，名称放第二行 |
| 「回执让它口头报就行」 | 执行者窗口输出主控读不到；回执必须落盘到回执目录，缺回执按未完成处理 |
| 「八项必查就够」 | 首行与唯一码是第九项：没有码，多窗并行时截图对不上卡 |

## 完成自检

- [ ] 卡文七段齐全、九项必查全过；起始 commit 等于当前 `main` 头；卡文落盘在仓库外
- [ ] 卡文首行只有 `卡<N>-<码>`（≤7 字符），名称从第二行开始；码与回执文件名一致
- [ ] 复核前回执已落盘且字段齐全（分支与提交、七条门禁、PASS 文件数、行数、用例、自检、定夺项）
- [ ] 卡文里的文件路径、欠账编号、docs 节、测试文件名在仓库里真实存在（或明确标「新增」）
- [ ] 派卡后真源库校验：`permission.mode=yolo`、模型与 `variant` 符合 profile
- [ ] watcher 在跑，四条退出条件齐全；启动前已确认有在跑任务
- [ ] 复核三条红线逐条给出「过/不过 + 文件与行」
- [ ] 分支上跑过一次全量门禁且退出码 0；合并后按树相等判据决定是否再跑，并在回执里写明理由
- [ ] worktree 与分支已清理，`git worktree list` 只剩应留项
- [ ] 账本四段齐全，「下一步」是可执行的第一步
- [ ] 接续时：账本先落盘、新会话开在 DSH 且标题为 `接续#N · 项目 · 日期`、watcher 与定时已重建、旧会话定时已删
- [ ] 定时只剩当下需要的（到点收尾与必要的降级）

## 资源清单

- `references/boundary-facts.md`：界面与真源的实测判据差异（权限、思考强度、取帧、折叠、假红）。
- `references/project-profile.md`：项目常量（仓库路径、门禁命令、执行者参数、额度窗口、并发上限）。
- `references/card-template.md`：卡文七段模板、九项发卡必查、设计类卡额外槽位、验收判据三铁律、交接场景的核对表。
- `references/zcode-ui.md`：ZCode 窗口内的点击（新建任务、选项目、模式、模型与思考强度、坐标纪律、停卡重派）。
- `references/watcher.md`：任务状态库、三证据判定、四条件退出、脚本骨架。
- `references/quota-check.md`：额度检查路径与判读口径。
- `references/session-handoff.md`：派卡（ZCode「新建任务」）与主控会话接续（DSH「新会话」）的分流表、落盘清单、交接提示词与重建自检。
