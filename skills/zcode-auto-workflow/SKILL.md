# ZCode 自动工作流

一句话：把「写卡 → 派给 ZCode → 盯到终态 → 复核 → 串行门禁 → 合并 → 清理 → 再派」做成可无人看管执行的循环，到约定时刻收尾；界面点击以当场截图为准，所有动作留证据。

默认产出：单卡模式一条派卡回执或盯卡结论；夜班模式每轮一条状态播报，收尾一份交接账本。

## 何时用 / 何时不用

| 用户意图 | 去哪 |
|---|---|
| 「派卡给 ZCode」「发给 ZCode」「开个新任务跑这张卡」「看看跑到哪了」「ZCode 卡住了」 | 本技能 · 单卡模式 |
| 「我睡了，交给你监管」「夜间自动推进」「盯 ZCode 到早上」「每批派两张卡」「8 点收尾」「10 点看额度」 | 本技能 · 夜班模式 |
| 只写代码、跑测试、Git 操作，不涉及 ZCode 界面 | 直接用相应工具 |
| 需要用户在场拍板（真机观察、方向取舍、界面验收） | 停手，等用户醒 |

判据：动作落在 ZCode 界面上，或要按任务卡循环推进的，用本技能。单卡模式只走第 2–7 步一次并出回执，不进循环、不派下一批。

## 输入与缺省

| 项 | 缺省 | 缺了怎么办 |
|---|---|---|
| 卡文 | 无 | 按 `references/card-template.md` 写一张；没有卡文不派卡 |
| 项目 | 上次用过的工作区 | 界面核对项目芯片，不一致就重新选 |
| 模式 | 完全访问 | 用户另有约定按用户 |
| 每批卡片数 | 2（10:00 后降为 1） | 用户明确说过上限就以用户为准；上限含这些任务开出的子智能体 |
| 收尾时刻 | 用户指定 | 没指定就默认「额度到期前 1 小时」 |
| 额度检查时刻 | 10:00 | 用户另指定按用户；别自造别的时刻 |
| 门禁命令 | 项目自带（如 `python scripts/gate.py`） | 没有就问用户（一次只问一个） |

## 第 0 步：环境检测与降级

依次确认，缺一项写明「降级/未做」与少了什么证据，不假装跑过：

1. ZCode 进程在跑、窗口可见（列出窗口确认标题与位置）；前台被别的应用占据时先尝试提到前台，提不到就带容忍焦点继续，并在回执注明。
2. 任务状态库可读：`%USERPROFILE%\.zcode\v2\tasks-index.sqlite`；先 `SELECT DISTINCT task_status` 核对状态枚举（见 `references/watcher.md`）。
3. 仓库可写、`git status` 干净、记下 main commit；一卡一 worktree，worktree 目录不重叠。
4. 门禁命令真实存在——先跑一次；红了先排除两类环境性误报（并行门禁互抢全局资源、宿主代理把回环别名流量送进代理），不是环境问题就停手问用户。
5. 定时唤醒可用（`schedule_*`）；不可用则每轮结束明确告诉用户「下次唤醒要你手动」。

降级声明写进第一条播报，不带过的意思。

## 主流程（8 步，每步有判据）

1. **读交接**：读项目交接文档、白板、最新交接账本。判据：能复述 main commit、在跑卡片、待合并分支、下一步候选；单卡模式只需复述项目与 main。
2. **写卡**：一卡一 worktree；卡文含 worktree 定位、停手约束、质量审查尾部。判据：三项齐全（见 `references/card-template.md`）。
3. **派卡**：按界面五动作操作——新建任务 → 选项目 → 模式选「完全访问」→ 粘贴卡文 → 回车发送（细节与坐标纪律见 `references/zcode-ui.md`）。判据：会话标题=卡文首行、侧栏任务列表出现该任务、模式芯片显示「完全访问」。
4. **盯到终态**：任务状态库查状态，再用三条证据判断「真的在干活」（worktree 新提交、未提交改动、ZCode 会话文件 mtime）。判据：四项齐——状态、分支与提交数、门禁结论、交付物检查行。
5. **复核 diff**：逐分支看 diff，查三条红线——交付物只写「此刻为真」（不写改动史）、无调试残留与死代码、新行为有测试。判据：每条红线给出「过 / 不过 + 证据（文件与行）」。
6. **串行跑门禁**：一次只跑一个 worktree/主工作区的门禁；红先排除环境性误报，确认不是环境问题才动产品代码，修不了就记录原因并跳过该卡。判据：主工作区门禁退出码 0，并报出检查项数量（如「N 文件交付物 PASS」）。
7. **合并与清理**：`git merge --no-ff <branch>`；冲突按语义取并集（双方各加的行都保留），不整段覆盖。合并后复跑门禁；删已合并 worktree 与分支，保留未合并的与用户个人分支。判据：合并后工作区干净、门禁复跑仍绿、`git worktree list` 只剩应留项。
8. **播报并派下一批**：一条状态 + 下一步；下一批按并发上限派，派完挂完成监听。判据：播报同时有「已完成 / 在跑 / 下一批候选」，监听作业在跑。

## 并发上限与巡检（硬约束）

- 免费额度下并行会话总数 ≤3（含子智能体）；超了就等终态再派。
- 夜班 10:00 前最多 2 张卡并行；10:00 后 1 张，前一张到终态才派下一张（含子智能体）。
- 无人看管期间挂每 2 小时一次的巡检唤醒（见 `references/watcher.md`「防卡死巡检」）：只查状态、处理卡死、报一行；不审查、不合并。

## 额度检查（缺省 10:00）

按界面路径逐级检查，记录「看到什么 + 结论」，不要猜（细节见 `references/quota-check.md`）：

1. 主界面看有没有醒目的「送额度」卡片，读出数量与有效期。
2. 点用户头像或名称，看弹出的菜单/卡片里有没有奖励或赠送。
3. 进设置（入口在侧栏底部图标行，先截图定位）→ 按层级点进模型/配额页 → 上下滚动看全部额度与到期时间。
4. 口径：**整体额度**（总额度池，通常亿级、有固定到期时刻）比**每日额度**（每天重置的小份）耐用；两者分开记。
5. 结论三选一：出现大额度 → 领取后继续推进；整体额度仍充裕 → 按计划继续；额度告罄或什么都没有 → 收工。
6. 收工时删掉为夜班设的巡检/收尾定时，避免空转唤醒。

## 到点收尾

不再派新卡；等在跑的卡到终态；能合的全合；worktree 清理；写交接账本（四段式）；报收尾摘要。

## 上下文健康（防止长会话拖崩）

- 每轮结束都要有可续命的落盘：日志一条 + 交接账本一段。
- 会话上下文占用到用户设的阈值（常见 40%）时换会话：先写交接账本，再在界面新建会话，把交接提示词发进去（步骤见 `references/session-handoff.md`）；换不动就退化为压缩，压缩不能替代落盘。
- 换会话后第一件事是重读交接账本，确认「main 位置、在跑卡片、未合分支、下一步」四项没丢，并在新会话里重建定时与监听。

## 输出模板（缺项不算完成）

派卡回执：

```
已派：<卡名> / <分支> / <worktree>
模式：完全访问
卡文：<卡文文件路径>
监听：<作业名 / 轮询方式>
```

盯卡结论：

```
状态：<运行中 / 完成 / 失败>
分支：<分支名> <提交数>
报告要点：<完成判据 / 门禁结论 / 待办>
```

夜班播报：

```
进展：<一句话>
已完成：<卡名 / 分支 / 合并 commit / 门禁结论>
在跑：<卡名 / 分支 / 起始时间 / 是否正常>
未合：<分支 / 原因>
下一步：<立即执行的第一件事>
```

## 停止规则与反合理化

| 借口 | 驳回 |
|---|---|
| 「坐标我记着，直接点」 | 一次截一张，坐标会漂 |
| 「先粘卡文再选项目也行」 | 选项目会清空输入框 |
| 「模式默认就行」 | 默认是自主模式，会卡审批 |
| 「先合并，门禁回头再跑」 | 合并在门禁之后，顺序不可换 |
| 「冲突很小，整段用他们的」 | 冲突按语义取并集，覆盖等于丢改动 |
| 「并行跑门禁更快」 | 已知会误报，串行是硬要求 |
| 「额度还有，先不看」 | 到点必须查，查完才能决定继续或收工 |
| 「上下文还够，不写账本」 | 账本是唯一跨会话记忆，每轮都写 |
| 「卡很久没动静，再等等」 | 超过阈值就判疑似卡死，按巡检规则处置 |
| 「再派一张试试」 | 并发上限是硬约束：10:00 前 ≤2、之后 1，超了先等终态 |

## 完成自检

- [ ] 项目芯片核对过，模式标签是「完全访问」
- [ ] 会话标题=卡文首行，任务列表可见，监听在跑
- [ ] 每条判据都有证据（commit、退出码、文件行、截图）
- [ ] 每卡一 worktree，未合分支仍在
- [ ] 门禁在主工作区复跑全绿
- [ ] 并行数在上限内（10:00 前 ≤2、之后 1），巡检定时在跑
- [ ] 交接账本四段齐全且「下一步」是可执行的第一步
- [ ] 定时任务只剩当下需要的
