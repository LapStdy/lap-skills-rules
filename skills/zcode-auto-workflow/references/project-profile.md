# 项目常量（换项目只改这一份）

卡文、脚本、巡检都从这里取值，不要把这些值抄进卡文正文。

| 项 | 值 | 说明 |
|---|---|---|
| 项目 | lap-backstop | 通用调度与监督平台 |
| 仓库路径 | `D:\lap-backstop` | 主工作区，分支 `main` |
| 门禁命令 | `python scripts/gate.py` | 串行跑，只在主控侧跑 |
| 交付物检查 | `python scripts/check_artifacts.py .` | 交付前必跑，回复里报一行 |
| 开工必读 | `AGENTS.md`、`docs/10-工程宪法.md`、`docs/11-代码规约.md` | 卡文里写「按 profile 的开工必读」即可 |
| 待办清单 | `TASKS.md`（待做）、`DEBT.md`（欠账） | 卡内不改，合并后由主控改 |
| worktree 前缀 | `D:\lap-backstop-card<N>` | 与主目录同级 |
| 分支前缀 | `feat/card<N>-<slug>` | 一卡一分支 |
| 卡文与脚本目录 | `D:\lap-work\.zcode\inbox\`、`D:\lap-work\` | **放在仓库外**：卡文里会出现「上一版本」「历史」这类词，被交付物检查当成改动史误报 |

## 执行者（ZCode）参数

| 项 | 值 | 说明 |
|---|---|---|
| 模型 | `GLM 5.3 Flash` | 新任务页选择；每次新建都要核对 |
| 思考强度 | `最高` | 界面默认是「高」，**必须逐个改成最高**并截图核对 |
| 降档条件 | 同一张卡因**网络繁忙**中断 ≥2 次 | 可降到「高」，并把降档原因写进播报 |
| 并发上限 | 2 张卡 | 含这些任务开出的子智能体 |
| 模式 | 完全访问 | 默认是自主模式，会卡审批 |
| 额度窗口 | 免费额度仅 `00:00–10:00` 可用 | 窗口外不派新卡；免费额度优先级低，可能排队 |
| 到期收尾 | 每天 `10:00` 必须收尾 | 到点停止派新卡，等在跑卡终态后合并、清理、报摘要 |

## 项目级注意

- 会话级限制：定时任务、后台作业不跨 DSH 会话；换会话或接续后先重建再干活。
- 中文标题在脚本里要显式 UTF-8，否则状态库读取会乱码。
- 门禁并行跑会互抢全局资源导致误报，永远串行。

## 实测基准（2026-11-01 首个完整值守夜）

| 项 | 实测值 | 用途 |
|---|---|---|
| 单卡耗时 | 30–80 分钟 | 排下一批时估算能否在窗口内收口 |
| 一夜吞吐 | 12 张卡 / 53 个提交 / 82 个文件 / +6742 行 | 排量参考 |
| 派卡失败率 | 10 批里 2 批失败（20%） | 派卡是全流程最高风险环节，必须真源核验 |
| 门禁单次耗时 | 约 210–230 秒 | 合并前后各一次，按 8 分钟预算 |
| 单夜水位涨幅 | 25% → 33% | 阈值 0.40 时整夜通常不触发接续 |
| rebase 需求 | 12 张里 5 张需要，全部无冲突 | 一卡一 worktree 的隔离够用 |
