# 边界事实：界面 ≠ 真源（实测）

这一页只写实测出来的判据差异。**界面显示不等于生效**，凡是能查真源库的，一律查真源库。

真源库：`%USERPROFILE%\.zcode\cli\db\db.sqlite`（只读打开）。
不可当判据的库：`%USERPROFILE%\.zcode\v2\tasks-index.sqlite` —— 运行中任务的 `mode` 列恒为 `default`、`task_status` 恒为 `NULL`，只有到终态才写真实值。

| 项 | 界面看起来 | 真源判据 | 处置 |
|---|---|---|---|
| 完全访问 | 模式芯片显示「完全访问」 | `session.permission` 为 `{"mode":"yolo"}` | 芯片只是草稿态；必须从别的模式切回并在「要启用完全访问吗」弹窗勾风险确认、点「确认启用」才写入 |
| 思考强度 | 芯片显示「最高」 | `model_usage.variant` 为 `max` | 芯片可能继承上次设置；做一次「低 → 最高」往返再核对 |
| 模型 | 模型弹窗显示 `GLM-5.3-Flash` | `model_usage.model_id` | 以库里为准 |
| 任务进度 | 侧栏转圈 / 「工作中」 | `updated_at` 与 worktree 提交 | 状态只说明在跑，有没有进展看 worktree 与会话文件 mtime |
| 会话标题 | 侧栏折行显示 | 库里的标题是正文前 60 字折行 | 不要用标题判等卡文首行 |

## 界面操作的边界

- **两个「新建」分属两个应用**：ZCode 窗口标题 `ZCode`、侧栏「新建任务 / 任务列表 / 项目」；DSH 窗口标题 `<会话标题> — DeepSeek Harness`、侧栏「新会话 / 工作区 / 会话」。两套侧栏都有项目/工作区列表、都靠悬浮露出「+」，点错不报错，只留下空任务或空上下文。派卡只在 ZCode，接续只在 DSH。
- **ZCode 侧栏只看到项目、看不到任务**：任务列表折叠在项目行下，点一下项目行才展开；状态库也看不到折叠项。
- **取帧只用窗口帧**：全屏帧是缩放图（实测 1708×961），据它估读坐标会偏 20–30 px。窗口帧（`screen_view(window=ZCode)`）是 976×809、1:1，窗口原点在屏幕 `(-8, 0)`，屏幕坐标 = 帧内坐标 + 原点。
- **悬停会抓错窗口**：指针停在按钮上会出现 tooltip 小窗，按窗口名取帧可能抓到那个几十像素的小图；先把指针移到空白处。
- **Esc 可能被别的程序占用**：本机 DSH pilot 抢了 Esc，按下取消的是 pilot 自己的动作。关下拉与弹窗点界面空白处。
- **风险确认勾选框点偏十像素会静默点空**：勾完必须回帧确认勾选框变实心、且「确认启用」由灰转亮红。
- **不要复用旧草稿会话**：新建任务必须是全新任务，复用旧草稿会把旧权限记录带进来（实测落成过「自主模式」）。

## 工程侧的四条边界

- **卡文不能放仓库内**：卡文里的「回滚到上一版本」这类句子会被交付物检查判成「历史渗入」，工作树外的目录才行（profile 里有具体路径）。
- **门禁假红**：主区跑门禁时执行者可能同时在跑测试抢全局资源。单条用例单独跑通过 + 整包复跑通过 ⇒ 判为并行抢资源，记录后继续，不改产品代码。
- **用例可能把宿主打掉**：`os.kill(pid, 0)` 在 Windows 上不是存活探测（`0` 是 `CTRL_C_EVENT`），测试进程内直接 `taskkill /T /F` 也可能连带结束调用者。现象是全量门禁在 pytest 中途终止、pytest 栈停在 `Thread.join` 或 `subprocess._communicate`，宿主 shell 一起退出且没有输出。判别：隔离控制台单跑该文件，能复现「测试打掉宿主」；修法是用内核句柄探测存活、强杀走隔离控制台（见 `rules/windows-process.md`）。
- **watcher 基线盲区**：watcher 只认「非终态 → 终态」的变化；启动时已终态的任务永远不会再触发。启动前先看一次状态，已无在跑任务就直接处理。
