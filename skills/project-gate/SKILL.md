# 项目门禁（project-gate）

一句话：把「完成」从口头约定变成一条命令；先有门禁，再谈速度。

默认产出：`scripts/gate.py` + 项目 `AGENTS.md` 的完成判据段 + 一次真实的造红验证与全绿输出。

## 前置条件

| 依赖 | 要求 | 缺了怎么办 |
|---|---|---|
| git 仓库 | 工作区可读、有提交（门禁结论要对应到提交） | 没有 git 也能接检查，但结论无法锁到版本，写明「无版本锚」 |
| Python 3.11+ | 项目 `scripts/` 可写（装两个检查器与门禁骨架） | 只读环境只能产出方案，不能落地 |
| 项目工具链 | `ruff`、`mypy`、`pytest`、`import-linter` 按项目选装 | 必需项缺工具按 FAIL；可选项缺工具 SKIP 并列出证据缺口 |
| 写权限 | 可改项目 `AGENTS.md` 与 README | 无写权限时只给补丁内容，由用户贴 |
| 时间预算 | 全量门禁一次能跑完；超过 5 分钟要拆快检与全量 | 跑不完就先接最小三条（格式、测试、交付物） |

## 何时用 / 何时不用

| 用户意图 | 去哪 |
|---|---|
| 「给这个项目搭门禁」「加质量门禁」「一条命令验完」「新项目开工」 | 本技能 |
| 「该不该上这类检查」「先做哪个」 | `first-principles` |
| 「派卡给执行者去加门禁」 | `zcode-auto-workflow`（本技能只产出方案与文件） |
| 已有门禁、只是红了 | 直接按 `rules/gates.md` 判真红假红，不用本技能 |
| 单个函数的命名与契约 | `function-spec` |

判据：用户要的是「一条命令能验完项目」→ 本技能；问「值不值得」→ 先 `first-principles`。

## 输入与缺省

| 项 | 缺省 | 缺了怎么办 |
|---|---|---|
| 项目目录 | 当前目录 | 问一次 |
| 语言栈 | 从 `pyproject.toml`、`package.json`、`go.mod` 推断 | 推断不出就问一次 |
| 已有检查 | 扫描 `scripts/`、`[tool.*]`、CI 配置并试跑 | 没有就按最小三条起步 |
| 项目 `AGENTS.md` | 有则追加章节，没有则用仓库模板生成 | 用 `tools/bootstrap.py` |
| 允许清单 | 空 | 只有既有超限才建，并在 DEBT 记账 |

## 第 0 步：现状检测

一条一条过，缺哪项就写明「降级/未做」与少了什么证据：

1. `git status` 干净，记下 `main` 头；门禁结论要能对应到具体提交。
2. 列出已有检查命令（`scripts/`、`pyproject` 的 `[tool.*]`、CI 配置）并逐条试跑，能跑通的保留。
3. 查工具：`ruff`、`mypy`、`pytest`、`import-linter`；缺的写进「证据缺口」。
4. 记测试规模与耗时：决定哪些进全量、哪些进快检。
5. 判断项目 profile（见 `rules/project-structure.md`），决定要不要结构检查与交付物检查。

## 主流程（6 步）

1. **定判据**：一句话写清「什么算完成」——退出码 0 且哪几类检查全绿；同时写进 README 与项目 `AGENTS.md`。
2. **选检查**：按最小三条起步（格式 + 测试 + 交付物），每加一类都对应一个真实发生过的问题；不配「看起来齐全」的检查。
3. **生成门禁**：复制仓库 `templates/gate.py` 到项目 `scripts/gate.py`，按项目改 `CHECKS`；缺工具的可选项标 `必需=False`。
4. **接常驻入口**：项目 `AGENTS.md` 写完成判据段与 `python scripts/gate.py`；README 写命令与全量耗时。
5. **造红验证**：临时改坏一行，确认退出码 1 且报对文件与行，再撤销；另造一次「必需工具缺失」，确认报 FAIL 而不是静默跳过。
6. **记账**：既有超限进 `structure-allow.txt` 并在 DEBT 记账；没做完的检查进 TASKS；提交说明写门禁项数与首次全绿耗时。

每一步的完成判据：

| 步 | 判据 |
|---|---|
| 1 | 判据出现在 README 与 `AGENTS.md` 两处且字面一致 |
| 2 | 每类检查能说出「它抓的是哪次真问题」，说不出就删 |
| 3 | `python scripts/gate.py --list` 能列出全部检查与必需/可选 |
| 4 | 新会话只读 `AGENTS.md` 就能跑出同一结论 |
| 5 | 两次造红都按预期失败；撤销后全绿，且没有 SKIP 的必需项 |
| 6 | 允许清单每条都有 DEBT 编号或归还期限 |

## 输出模板（缺项不算完成）

```
门禁：<N> 项（必需 <X>，可选 <Y>）
入口：scripts/gate.py
报告行：门禁：PASS（N 项）
首次全绿：<日期> <耗时>
允许清单：<N> 项（既有超限，见 DEBT <编号>）
造红验证：<两次，各自现象>
下一步：<第一个可执行的补检查动作>
```

## 停止规则与反合理化

| 借口 | 驳回 |
|---|---|
| 「一次配齐七类最稳」 | 每类都有维护成本；先三条，出过问题再加 |
| 「本地跑不过，等 CI 再说」 | 门禁的价值是本机一次跑完；CI 只是复跑同一命令 |
| 「允许清单先加满，以后再说」 | 清单只缩不涨；新增条目必须带归还期限 |
| 「测试太慢，门禁只跑改动包」 | 连带影响正是门禁要抓的；慢就拆快检与全量，合并判据用全量 |
| 「检查工具没装就先跳过」 | 必需项缺工具按失败，可选项才允许 SKIP 并写出证据缺口 |
| 「先跑起来，判据回头写」 | 没有判据的门禁无法判定红绿；判据先写 |
| 「门禁红了先改代码」 | 先复现；能复现才算缺陷，否则按假红判据处理 |

## 完成自检

- [ ] `scripts/gate.py` 一条命令跑完全部检查，串行、失败即停
- [ ] 必需与可选分清；缺工具行为写死（必需 FAIL、可选 SKIP 并报证据缺口）
- [ ] 项目 `AGENTS.md` 与 README 都写了命令与判据，字面一致
- [ ] 造红验证做过两次：改坏代码、必需工具缺失
- [ ] 全量耗时写进 README；超过 5 分钟区分快检与全量
- [ ] 既有超限有允许清单与 DEBT 记账
- [ ] 首次全绿输出贴进了交接账本

## 资源清单

- 仓库 `templates/gate.py`：门禁骨架（七类检查、必需/可选、失败即停）
- 仓库 `tools/check_structure.py`、`tools/check_artifacts.py`：复制进项目 `scripts/`
- `references/gate-checks.md`：七类检查的落地命令与踩坑
- 规则：`rules/gates.md`（合并判据与假红）、`rules/testing.md`（测试稳定性）、`rules/ledger.md`（记账）
