# 函数规范（function-spec）

按「通用函数规范 v0」逐条检查单个函数或小 diff，产出命中表、契约摘要与可机械判定的结论。默认只报 MUST 级问题，默认不改代码、只给最小改写示例。

## 何时用、何时不用

| 用户意图 | 走哪里 |
|---|---|
| 这个函数写得怎么样、怎么改；命名/参数/职责/纯度/副作用/错误契约/docstring/类型/太长/圈复杂度 | **本技能** |
| 整个 PR/分支「是否符合规范 + 是否实现需求」 | `code-review`（双轴评审） |
| 线上报错、堆栈、要定位根因 | `diagnosing-bugs` |
| 模块边界、分层、循环依赖 | `brooks-audit` / `codebase-design` |
| 0–100 评分、腐化归类、书单式论证 | `brooks-review` |
| 从零写测试驱动实现；测试腐化/脆测试 | `tdd`；`brooks-test` |
| 该不该写/改这个函数、方案取舍、有没有更优解 | `first-principles` |
| 性能基线、热点、benchmark、防回归 | `perf-evidence` |

判据：用户问「这个函数怎么改」→ 本技能；问「这次改动对不对/需求实现了没」→ `code-review`；问「为什么报错」→ `diagnosing-bugs`。
命中相邻技能时，一句话说明路由理由并给出相邻技能名，**不要产出本技能的命中表**。

## 输入与缺省

| 项 | 缺省 |
|---|---|
| 函数源码或 diff | 必填；没有就问一次 |
| 语言 | 按扩展名推断；无扩展名问一次 |
| 严格度 | 只报 MUST；用户说「严格/全都看」才加 SHOULD |
| 是否产出 patch | 否，只给改写示例；用户要 patch 才给最小 diff |
| 项目约定 | 先读 `AGENTS.md`、`CODING_STANDARDS.md`、`pyproject.toml` 的 lint 配置 |

缺输入时先从仓库读；读过仍缺的，一次只问一个必填项，不要列一串问题。

## 第 0 步：工具检测与降级（必做）

依次探测 `python -m ruff --version`、`python -m mypy --version`、`python -m radon --version`；报错即视为缺失。

| 情况 | 做法 |
|---|---|
| 工具齐全 | N4/S3/E4/G1/G2 用工具结果，报告里注明工具与版本 |
| 部分/全缺 | 跑 `python scripts/metrics.py <file> --json`（零依赖 AST）拿候选证据；缺失项改人工判定 |
| 完全无工具、无测试 | 仍可审：AST 指标 + 人工规则表；**不得**回答「无法审计」 |

降级必须明写：缺了哪些工具、哪些判据从自动改为人工/AST、结论少了什么可信度（例如「无 mypy：只验证注解存在，不验证类型兼容」）。**不假装跑过工具**；报告注明证据形态（工具输出 / AST 指标 / 人工判据）。TS 的 T2/S3/T1 分支无 `tsc --strict` 时标「待工具」，不判 FAIL。

## 流程（7 步，每步有完成判据）

| 步 | 做什么 | 完成判据 |
|---|---|---|
| 1 | 读函数、调用点、项目约定 | 能写出输入域/输出域/错误类型/副作用 |
| 2 | 判语言与公共/内部；标出 IO 边界 | 每个 IO 调用有文件:行号 |
| 3 | 跑 `metrics.py`（或 ruff/mypy/radon） | 行数/参数/布尔开关/嵌套/副作用/重复定义有数字 |
| 4 | 按 29 条规则逐条过（九组） | 每条 MUST 有 ✅/❌；默认只输出 ❌ |
| 5 | 单独核错误契约 E1–E6 与契约三档（L1 文档 / L2 代码） | 失败语义全模块一致；无值域哨兵 |
| 6 | 生成最小改写/补丁 | 行为不变；不改公共签名语义，除非标 BREAKING |
| 7 | 输出三件套 | 结论可机械判定：MUST 命中数 = 0 |

`metrics.py` 的 `candidates` 只是候选证据，不是判定；每条都要人工复核后才进命中表。

## 规则速查（29 条，细则见 references）

| 组 | ID | 管什么 |
|---|---|---|
| 命名 | N1–N4 | 动词短语/snake_case；名字暴露副作用与代价；纯属性不包 get_；不重复定义同名函数 |
| 签名 | S1–S4 | 参数 ≤4、布尔开关 ≤1；禁可变默认参数；公共 API 参数与返回全注解；不滥用 *args/**kwargs |
| 职责 | R1–R4 | 一句话说清职责；查询与命令分离；一个函数一个抽象层；副作用只在边界 |
| 纯度 | P1–P3 | 禁 import 期副作用；副作用参数注入；有副作用函数幂等或标「不可重试」 |
| 错误 | E1–E6 | 可预期失败返空值、不可预期抛异常；禁值域哨兵；模块内一致；禁裸 except；assert 只放不变量；异常消息可 grep 且带出错值 |
| 文档 | D1–D2 | 公共函数有 docstring；复杂函数写 Args/Returns/Raises |
| 类型 | T1–T2 | 不用 Any 兜底；TS 导出函数显式返回类型 |
| 规模 | G1–G2 | ≤50 行；圈复杂度 ≤10、嵌套 ≤3 |
| 可测 | X1–X2 | 纯函数可不启外部世界直测；性能敏感函数有 benchmark 且断言正确性 |

MUST：N1/N2/N4、S1/S2/S3、R1/R2/R4、P1/P2、E1–E5、D1/D2、T1、X1。其余 SHOULD。
D1/D2 的 MUST 是团队选择（PEP 257 原文为 should）；评审第三方代码按 SHOULD。
完整规则、出处 URL、反例、豁免与误报防守见 `references/function-standard-v0.md`；核对 E1–E6 时再读 `references/error-contract.md`（两类失败、哨兵、assert 边界、契约三档）。

## 输出模板（三件套，缺一不算完成）

**1) 命中表**——每条一行，列不可省：

| 规则 ID | 级别 | 证据（文件:行号） | 现状 | 改法 | 一手来源 |
|---|---|---|---|---|---|
| E4 | MUST | `parser.py:13` | 裸 `except:` 吞掉全部异常 | 只捕 `OSError/JSONDecodeError`，`raise X from Y` 保留因果 | https://peps.python.org/pep-0008/ |

只输出 ❌ 项；✅ 项汇总成一行（如「N/S/R/P/E/D/T/G 已过，MUST 命中 3 条」）。豁免项单列并写 `# std-exempt:` 理由。

**2) 契约摘要**——五行，缺一行都不算：

```text
输入域：<合法输入与前置条件>
输出保证：<返回什么、范围/不变量>
错误类型：<可预期失败返回什么 | 不可预期抛什么异常>
副作用：<无 | 写哪里、幂等性>
幂等性：<可重复调用是否安全；不可重试要写明>
```

**3) 结论**——一行机械判定：`MUST 命中数 = N → 通过 / 不通过`。N=0 才通过；不通过时按严重度排序给 1–3 条优先修。

报告只含以上三件套与豁免说明；不要附加大段边界声明或打分。

## 豁免与误报防守

- 豁免：超阈值有理由、跨语言惯例冲突、生成代码、第三方接口适配层——函数上方一行 `# std-exempt: <理由>`，报 WARN 不报 FAIL。
- 报 FAIL 前先核这些常见误报：
  - **N3**：getter 有取值代价或副作用时，`get_` 合理。
  - **S1**：参数 >4 但语义明确且全用关键字调用 → 最多 SHOULD 提醒。
  - **E1**：返回 `Optional[T]` 是文档化契约，不是与异常混用。
  - **D1**：dunder、测试函数、一行内部闭包可不写 docstring。
  - **T1**：外部边界用 `object`/`unknown` 并就地收窄是标准做法，不算 `Any` 兜底。
  - **G1**：生成代码、查表/配置数据不受行数阈值约束。
- 口径：MUST 只在「能给出改法且不改坏行为」时报 FAIL；证据不足降级为「待确认」并写清缺什么证据。

## 反合理化（遇到这些说法直接驳回）

| 借口 | 驳回 |
|---|---|
| 测试全绿，所以函数没问题 | 测试只抽样输入；契约混用、哨兵、裸 except 往往测试照绿 |
| 能跑就别动 | 本技能查的就是「能跑但契约错」 |
| 参数多但都有用 | 改配置对象或关键字参数，行为不变；S1 是 MUST |
| 返回 -1 调用方都认识 | 值域哨兵 E2；统一返 `None` 或抛领域异常，二选一并全模块一致 |
| 没 ruff/mypy 没法审 | 降级：AST + 人工规则表，写明少了什么，不拒绝审计 |
| 改名会 BREAKING，所以不报 | 照报并标 BREAKING，给兼容别名/迁移说明 |
| docstring 以后补 | D1 是 MUST，一行祈使句摘要即可 |
| 只是内部函数，不用管 | R4/P2 与公共/内部无关；公共/内部只影响 S3/D1 的严格度 |

## 完成判据（自检）

- [ ] 每条 FAIL 有规则 ID + 文件:行号 + 一手来源 URL；无「我觉得」式结论
- [ ] 命中表、契约摘要、结论三件套齐全，结论可机械判定
- [ ] patch/示例不改变行为；不改公共签名语义，除非显式标 BREAKING
- [ ] 纯核心未引入 IO；错误契约未混用（空值 vs 异常）
- [ ] 缺工具时写明「降级」与少了什么，未假装跑过工具
- [ ] 未越界到相邻技能职责（模块设计、需求实现、评分类问题交给对应技能）
