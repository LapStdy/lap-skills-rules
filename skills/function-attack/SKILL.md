# 函数攻击（function-attack）

对已存在的单个函数做「正向属性 + 反向攻击」：按性价比顺序主动找未知缺陷，产出最小反例、存活变异体清单与残留风险。默认不改生产代码，只给测试/反例与最小修复建议。

## 何时用、何时不用

| 用户意图 | 走哪里 |
|---|---|
| 攻击这个函数、找未知 bug、反向/对抗测试、边界/负向测试、属性测试、变异测试、fuzz、差分/蜕变、测试没测到 | **本技能** |
| 已有 bug（报错/堆栈/「输入 3 个元素就崩」）要根因定位并修 | `diagnosing-bugs`（不要开攻击清单） |
| 从零写实现、先写哪个失败测试、红绿循环 | `tdd` |
| 测试本身的腐化/脆测试/过度打桩（静态体检，不执行） | `brooks-test` |
| 单个函数怎么写规范（命名/契约/docstring/复杂度） | `function-spec` |
| 性能慢、基线、benchmark | `perf-evidence` |
| 整个 PR 的规范轴 + 需求轴 | `code-review` |

判据：问「这个函数还有哪些未知缺陷 / 怎么证明没测漏」→ 本技能；问「为什么坏了 / 怎么修」→ `diagnosing-bugs`；问「测试写得烂不烂」→ `brooks-test`。
命中相邻技能时，一句话说明路由理由并给出相邻技能 id，随即停止；**不展开本技能的任何步骤或产物**。

## 输入与缺省

| 项 | 缺省 |
|---|---|
| 目标 | 函数路径 + 行号（或代码片段）；没有就问一次 |
| 契约 | docstring/类型/错误约定；缺失时先用 `function-spec` 的契约摘要五要素，或按调用点推导并标「假设」 |
| 调用点 | grep 所有调用点，确认输入来源、输出去向、副作用 |
| 现有测试 | 先跑一遍，记录基线绿/红 |
| 风险级别 | 低/中/高；高风险函数放大时间盒与抽样数 |
| 时间预算 | 默认 30–60 分钟，按步骤时间盒分配 |
| 是否改代码 | 否；只产出测试/反例/最小修复建议。用户要修才给 patch |

## 第 0 步：工具与平台检测（必做，先于攻击）

探测 `python -c "import hypothesis"`、`mutmut --version`、`python -c "import atheris"`；Atheris 仅 Linux/macOS 可用。报错即缺失。

| 情况 | 做法 |
|---|---|
| Hypothesis 可用 | 用 `@given`/`@settings` 写属性，失败自动 shrink |
| Hypothesis 不可用 | **降级**：手写生成器 + `pytest.mark.parametrize`，属性类型不变；报告写「降级」及少了 shrink/生成覆盖 |
| mutmut 可用（含 WSL） | 抽样变异，记录 killed/survived/timeout/unviable |
| mutmut 不可用 | **降级**：手工注入 5–10 个变异体（见 `references/mutation-playbook.md`），统计 survived |
| Atheris 可用 | 按 `references/fuzz-harness.md` 写 harness，跑 60–300 秒 smoke |
| Atheris 不可用（Windows 常见） | **未做 fuzz**，写清缺失与影响；改用 `scripts/probe_inputs.py` 做边界 smoke（固定输入集 + 异常分类），并说明它不是覆盖率引导 fuzz |

降级规则：缺工具不拒绝攻击；必须明写「降级/未做」、缺了什么、结论少了什么证据；**不假装跑过工具**。

## 8 步攻击清单（每步有判据与时间盒）

| # | 步骤 | 通过判据 | 时间盒 |
|---|---|---|---|
| 0 | 读契约与调用点 | 能写出输入域、输出域、错误类型、副作用、幂等/线程假设 | 5–10 min |
| 1 | 输入域 + 边界（正常 + 负向） | 每个高风险维度有测试或书面「不适用」理由；边界表见 `references/boundary-matrix.md` | 15–30 min |
| 2 | 错误契约 | 非法输入按契约失败；异常类型/消息/副作用/资源清理逐项核对；无脏数据/泄漏 | 10–20 min |
| 3 | 属性测试 3–5 条 | 覆盖 invariant + round-trip（若可逆）+ oracle/metamorphic 之一；全过，或失败给最小反例 | 30–60 min |
| 4 | 变异抽样 10–30（无工具手工 5–10） | ≥70%（关键函数 ≥80%）或每个 survived 有处置 | 10–30 min |
| 5 | fuzz（按需：解析/协议/安全边界） | 60–300 秒 smoke 无崩溃/超时/未捕获异常；有则最小化 | 30–90 min |
| 6 | 差分（有第二实现）/ 蜕变（无 oracle 但有关系） | 无不一致；每个不一致已 triage | 30–60 min |
| 7 | 固化 + 稳定性 | 最小反例写成示例测试；重复 3–5 次/随机顺序通过；旧测试不受影响 | 10–20 min |

每步报告 ✅/❌/不适用；不适用要写理由，不能空白。

## 停止规则

- 低风险 + 步骤 1–3 全绿 → 可停在步骤 3；写明未做变异/fuzz 的理由。
- 变异分数低但函数是薄封装/纯转发 → 先判断「是否值得测」，可标 `skip` 并写理由。
- fuzz 连续多日无新覆盖 → 停止加时间，换 target 或换手段。
- **禁止用「测试全绿」当结论**；结论必须是「哪几步做了、判据是什么、还剩什么风险」。

## 输出模板（完整报告；缺项不算完成）

```text
目标：<path::func>（风险：低/中/高，预算：N min）
契约：输入域 / 输出保证 / 错误类型 / 副作用 / 幂等性
调用点：<文件:行号，输入来源与输出去向>
步骤：
  0 契约与调用点：✅/❌ <证据>
  1 输入域/边界：✅/❌ <维度表与用例>
  2 错误契约：✅/❌ <类型/消息/副作用/清理>
  3 属性：✅/❌ <3–5 条属性与结果>
  4 变异：抽样 N，killed X / survived Y / timeout Z / unviable U → 分数 P%
     存活：<变异体> → 处置（缺断言/等价/超时/接受+理由）
  5 fuzz：✅/❌/不适用 <种子、时长、崩溃与最小化>
  6 差分/蜕变：✅/❌/不适用 <第二实现或 MR>
  7 固化+稳定性：✅/❌ <回归用例、重复次数、flaky>
最小反例：
  输入：<最小输入>
  期望：<契约要求>
  实际：<观察到的结果/异常>
  复现：<可直接执行的命令>
未覆盖风险：<按影响排序，每条写为什么没覆盖、建议下一步>
```

报告只含以上内容；不要打分、不要做架构/需求评审。

## 最小反例规范

- 失败必须给**最小**可复现输入（自动 shrink 或手工删减），不要贴随机大输入。
- 四件套齐全：输入、期望、实际、复现命令；异常要给类型 + 关键消息。
- 一个失败一个反例；多个失败按严重度排序，不合并成模糊描述。
- 反例固化成示例测试后，保留属性测试作为防同类问题的护栏。

## 变异口径

- 分数 = `(killed + timeout) / (killed + timeout + survived + no-coverage)`；unviable/编译错误不计入分母。报告写清口径。
- 不追 100%：等价变异体无法自动识别，是固定损耗（见 `references/mutation-playbook.md`）。
- 每个 survived 必须四选一：补断言 / 标等价 / 标超时或不可用 / 接受（附理由）。
- 抽样要有范围与种子/命令，保证可复现。

## 反合理化（遇到这些说法直接驳回）

| 借口 | 驳回 |
|---|---|
| 测试全绿，所以没 bug | 测试只抽样输入；结论只能是「做了哪几步、还剩什么风险」 |
| 覆盖率 90%，够了 | 覆盖只证明执行过，不证明能发现故障；用变异/反例说话 |
| 属性测试写不出，跳过 | 降级为示例测试 + 边界表；属性类型（不变量/往返/幂等/oracle/蜕变）至少试一条 |
| 变异分数 100% 才行 | 等价变异体让 100% 无意义；看存活清单与处置 |
| 没装 hypothesis/mutmut，做不了 | 降级路径：手写生成器 + 手工注入变异；写清未做与影响 |
| 这是内部函数，不用攻击 | 攻击对象是契约风险，不是可见性；内部解析器/计算函数同样要测 |
| fuzz 崩了但复现不了，先放着 | 不稳定复现先查 harness 非确定性；不能稳定复现的崩溃不能当已发现 |
| 重构/优化后测试全绿就行 | 行为变化需要契约级证据；先跑本技能步骤 1–4 再谈重构 |

## 完成判据（自检）

- [ ] 8 步每步有 ✅/❌/不适用 + 证据；不适用有理由
- [ ] 至少 3 条属性，且不是同义反复（没有把实现抄成 oracle）
- [ ] 失败有最小反例四件套；报告末尾列未覆盖风险
- [ ] 变异有统计与每个存活体处置；分数口径写清
- [ ] 缺工具时写明「降级/未做」及少了什么，未假装跑过
- [ ] 未越界到 `tdd` / `brooks-test` / `diagnosing-bugs` 的职责
