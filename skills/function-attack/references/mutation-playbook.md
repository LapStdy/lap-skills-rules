# 变异测试 playbook（含无工具兜底）

> 用途：步骤 4。回答「现有测试能不能发现代码被改坏」，而不是「代码有没有 bug」。

## 1. 机制与口径

- 往源码注入小改动（mutant），每个 mutant 跑测试：失败 = killed，通过 = survived。
- **口径**（Stryker 定义，报告必须写清）：
  - detected = killed + timeout
  - valid = detected + survived + no coverage
  - mutation score = detected / valid × 100
  - unviable / 编译错误不计入分母（不同工具处理不同，跨工具比较前先核对）
- timeout 通常算 detected（测试挂死说明行为变了）；但要在报告里注明。
- **100% 不是目标**：等价变异体无法自动识别，是固定损耗。

## 2. 抽样策略

| 场景 | 范围 | 数量 | 预算 |
|---|---|---|---|
| 单函数攻击 | 目标函数所在文件/行 | 10–30 | 10–30 min |
| PR 门禁 | 变更文件/变更行 | 10–30 | 2–10 min |
| 夜间 | 模块级/全量 | 全量 | 30 min–数小时 |

抽样必须记录：工具与版本、范围、种子/参数、运行命令、时间。否则结论不可复现。

## 3. 变异算子类别

- **条件边界**：`<` ↔ `<=`、`>` ↔ `>=`；
- **条件取反**：`==` ↔ `!={B}、`and` ↔ `or`、加/删 `not`；
- **算术**：`+` ↔ `-`、`*` ↔ `/`、常量 +1/−1；
- **返回值**：返回 `None`/`0`/`1`/`""`、返回固定 `True/False`；
- **删分支**：删 `else`、删 `raise`、删早返回；
- **删副作用**：删写入/日志/回调/状态更新；
- **边界常量**：`0` ↔ `1`、`""` ↔ `None`、阈值 ±1。

## 4. 无工具兜底：手工注入 5–10 个

按上表类别，对目标函数逐个手改（临时副本/工作区，不提交），每改一个跑一次现有测试，记录 killed/survived。

示例（通用解析函数）：

| # | 变异 | 位置 | 预期被杀于 |
|---|---|---|---|
| 1 | 删除空串检查 | 入口 | 空串测试 |
| 2 | `if value < 0` → `if value <= 0` | 数值校验 | 0 值测试 |
| 3 | 失败返回 `None` → 返回 `-1` | 错误路径 | 错误契约测试 |
| 4 | `return value * 1000` → `return value * 100` | 换算 | 单位测试 |
| 5 | 删除 `try/except` | 异常处理 | 非法输入测试 |
| 6 | `text.strip()` → `text` | 预处理 | 空白输入测试 |
| 7 | `else` 分支返回改常量 | 分支 | 多分支测试 |
| 8 | 删除 `raise` | 错误路径 | 非法输入测试 |

**关键**：手工变异同样要记录「改了什么、哪条测试杀死了它、哪个活了」；survived 必须有处置。

## 5. 等价变异体三分法

| 类别 | 判定 | 处置 |
|---|---|---|
| 真等价 | 对任何输入语义相同（如冗余条件、恒真比较） | 标「等价」+ 理由；必要时重构消除 |
| 测试盲区 | 语义不同但现有测试没覆盖 | 补断言/补用例；这是变异测试的主要收益 |
| 不可用 | 编译错误、超时、环境不兼容 | 标 unviable/timeout，不计入分母，写原因 |

**禁止**：为了分数给等价体硬写测试；把「等价」当借口不写理由。

## 6. 存活体处置（必须四选一）

- **补断言**：写清补哪条断言、哪个输入；
- **标等价**：写清为什么任何输入都等价；
- **标超时/不可用**：写环境与原因；
- **接受**：写清风险与为什么不修（薄封装、生成代码、第三方边界）。

## 7. 工具与平台（2026-10 检索）

| 工具 | 语言 | 最小用法 | 平台约束 |
|---|---|---|---|
| mutmut | Python | `mutmut run` / `mutmut browse` | 需要 fork，**Windows 用 WSL** |
| cosmic-ray | Python | 配置 + 会话库流水线 | 配置较重 |
| StrykerJS | JS/TS | `npx stryker run --incremental` | Node 生态 |
| cargo-mutants | Rust | `cargo mutants --file/--in-diff` | Rust 工具链 |
| PIT | Java | Maven/Gradle 插件 | JVM |

**降级**：Windows 原生无 mutmut/WSL 时，不安装、不假装跑过；改手工注入并写明「降级，未做自动变异」。

## 8. 成本控制

- 只测变更文件/变更行；增量缓存；超时按 baseline 的 5 倍设。
- 单测套件 >2 分钟先提速，否则变异测试不可持续。
- 抽样 10–30 个足以发现「测试完全没断言」这类系统性问题；全量放夜间。

## 9. 报告格式

```text
变异：工具/手工；范围=<文件:行>；抽样 N
结果：killed X / survived Y / timeout Z / unviable U → 分数 P%（口径见上）
存活：
  - <变异位置与改法> → 处置：<补断言/等价/超时/接受>（理由）
口径说明：<timeout 是否计入 detected；unviable 如何处理>
```

## 10. 反模式

- 只报分数不报存活清单；
- 用「测试全绿」代替变异结果；
- 对生成代码/第三方代码大规模变异，噪声淹没信号；
- 跨工具直接比分数（口径不同）；
- 为提高分数删除/跳过测试。
