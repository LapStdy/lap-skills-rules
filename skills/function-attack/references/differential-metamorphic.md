# 差分测试与蜕变测试

> 用途：步骤 6。没有 oracle 时的两条路：用**另一个实现**当 oracle（差分），或用**输入变换关系**当 oracle（蜕变）。

## 1. 差分测试

**定义**：同一规格的多个确定性实现，对同一合法输入必须给出相同结果；不同即至少一个实现有错。

**适用**：重写/迁移（旧 vs 新）、两套独立实现（标准库 vs 手写）、不同配置/平台（单线程 vs 多线程、CPU vs GPU）、跨语言（Python 参考 vs Rust 加速）。

**harness 模板**：

```python
def compare(input_value):
    old = old_impl(input_value)
    new = new_impl(input_value)
    if old != new:
        return (input_value, old, new)  # 交给 triage

# 输入来源：属性测试生成器 / 固定边界表 / 线上采样（脱敏）
for value in generate_inputs():
    mismatch = compare(value)
    if mismatch:
        print(mismatch)
```

**比较规则**：

- 浮点用相对/绝对容差；集合用无序比较；字典比较键值集合；
- 错误路径比较异常类型/错误码，不比较完整文案；
- 输入必须落在两个实现都定义的定义域内；规格未定义处不算不一致。

**triage 三分类**：新实现错 / 旧实现错 / 规格未定义。每个不一致必须给结论，不能只列差异。

**成本**：要维护第二实现（最大成本）；适合迁移期，不适合从零写的新函数。

## 2. 蜕变测试（MR）

**定义**：对输入施加语义保持的变换，输出应满足可预测关系；不需要知道正确输出。

**通用 MR 目录**：

| 函数类型 | MR |
|---|---|
| 排序 | `sort(reverse(xs)) == sort(xs)`；排序不增删元素 |
| 求和/聚合 | `sum(xs + [0]) == sum(xs)`；加法结合顺序不影响结果（浮点用容差） |
| 编码/解码 | `decode(encode(x)) == x`（也是往返属性） |
| 线性函数 | `f(k * x) == k * f(x)`（k 在合法范围） |
| 清洗/规范化 | `clean(clean(x)) == clean(x)`（幂等） |
| 缓存/快路径 | 命中缓存与未命中结果一致 |
| 集合过滤 | 过滤不增加元素；过滤两次等于一次 |
| 单位换算 | `to_ms(to_s(x)) == to_ms(x * 1000)` 一类关系 |

**怎么找 MR**：

1. 从规格找「显然不应改变结果」的操作（加空元素、换顺序、等价表示）；
2. 从领域知识找守恒量（元素个数、总能量、校验和）；
3. 从实现找「两条路径应等价」（缓存 vs 直算、快路径 vs 慢路径）；
4. 用属性测试库承载 MR（MR 本质是一条属性），失败同样收缩。

**局限**：浮点舍入会误报；MR 本身可能写错；需要领域知识；对输出完全不可预测的场景无能为力。

## 3. 与回归测试的闭环

```text
fuzz / 差分 / 蜕变发现反例
        │ 最小化
        ▼
   示例测试（永久回归）
        │ 定期重跑
        ▼
   属性 / 变异测试（防同类问题、评估强度）
```

**判据**：每个不一致/反例都有最小输入、triage 结论、固化后的回归测试；差分 harness 可作为跨版本一致性门禁长期保留。

## 4. 不适用时怎么写

- 没有第二实现 → 「差分不适用：无独立参考实现」；
- 无法定义语义保持变换 → 「蜕变不适用：无领域 MR」；
- 不适用不等于跳过：仍要完成步骤 1–4，并在报告写理由。
