# 记忆整理（用户级记忆优化）

一句话：用户级记忆只留「每轮都必须生效、且只有它必须在这一层」的最小集合；其余下沉到技能或项目笔记，或删除。

## 前置条件

| 依赖 | 要求 | 缺了怎么办 |
|---|---|---|
| **DSH 记忆插件** | `memory_read`、`memory_rules`、`memory_user`、`memory_note`、`memory_status`、`memory_recall` 等工具可用 | 插件没装或缺工具：只输出分层建议与对照表，**不执行任何写操作**，明确写「未执行」；不手改 `MEMORY.md` 冒充执行 |
| 记忆文件 | 本机 `~/.dsh/memory/` 与当前工作区 `.dsh-memory/` 存在且可读 | 只有用户级、没有工作区记忆时，跳过「下沉到项目笔记」并写明 |
| 备份目录 | `~/.dsh/memory/workspaces/<ws>/archive/` 可写 | 不可写就停下，不裸改用户级记忆 |
| 用户确认 | 改用户级、删条目、下沉到技能都要先给对照表 | 未确认时只出方案，不动文件 |

## 何时用 / 何时不用

| 用户意图 | 去哪 |
|---|---|
| 「记忆太乱」「清理记忆」「优化用户级记忆」「记忆分层」 | 本技能 |
| 只是追加一条事实、写日志、更新项目笔记 | 直接用 `memory_log` / `memory_note`，不用本技能 |
| 想把一段操作流程固化成技能 | 按 `rules/skills.md` 写技能，不用本技能 |
| 想判断某条规则该不该进用户级 | 本技能（四问 + 分层表） |

判据：用户要的是「重排、合并、删减现有记忆」→ 本技能；只是追加一条 → 直接写。

## 第一性原理：先问四问，再动手

1. 这条每轮无条件注入，是为了防止哪个具体错误？说不出失效场景的，删。
2. 它只在特定触发下才需要吗？是 → 写进技能（description 里的触发词）或项目笔记。
3. 它只对本项目/本机成立吗？本机事实与路径 → 项目笔记；一次性决定 → 删除或归档。
4. 同一决策点是否已有别的条目覆盖？有 → 合并，不并列。

事实基座：一条 = 决策点（做什么 / 不做什么）+ 判据 + 例外；不写操作步骤、路径细节、技能正文。

## 分层判据

| 记忆形态 | 放哪 | 判据 |
|---|---|---|
| 每轮都要生效的硬约束 / 偏好 | 用户级 `MEMORY.md` | 漏了会当场犯错 |
| 有明确触发条件的操作规程 | 技能 `SKILL.md`（description 写触发词） | 只在某类任务里用 |
| 本机事实、项目路径、踩坑记录 | 项目笔记 | 只对本工作区成立 |
| 一次性决定、已完成方案 | 删除或归档 | 未来无行动价值 |

- 操作类知识一律进技能：多步骤 / 易错操作先加载匹配技能、正文按需加载，不凭印象改系统配置。
- 不要隐藏技能（加了隐藏开关模型会看不到、也调不动）；技能清单对模型始终可见。
- 技能改动先改仓库（GitHub LapStdy/lap-skills-rules），再 `python tools/install_skills.py <名>`，`--check` 归零才算装好；不手改安装副本。

## 流程（7 步）

1. **备份**：用户级文件复制到 `~/.dsh/memory/workspaces/<ws>/archive/MEMORY.user.bak-<yyyyMMdd-HHmmss>.md`。
2. **编号清单**：`memory_rules list` / `memory_read` 取全量，按文件顺序编号给用户逐条定夺；用户已指名处理的直接执行。
3. **逐条判**：四问 + 分层表 → 保留 / 合并 / 下沉 / 删除，每项写一句理由。
4. **排序**：按「违反后果 × 触发频率」从高到低；用户指名置顶的条目放第一条。
5. **执行**：单条改动用 `memory_rules update/remove`（带 expect 原文，防漂移）；整体重排用 `memory_user replace` 整份替换。
6. **下沉**：技能先改仓库再安装并 `--check`；项目笔记用 `memory_note append` 写并带来源日期；文件不进版本库的过渡方案只留指针。
7. **校验**：`memory_rules list` 条数一致；`memory_status` 字符数下降；文件首行是规则句而不是 `##` 标题；无重复决策点；每条保留项能一句话说出「漏了会怎样」。

## 规则写法

- 一条一决策点；先约束、再判据、最后例外。
- 单条 ≤120 字（超了多半该下沉）。
- 用「必须 / 禁止 / 一律」这类可执行词，不写「尽量」。
- 不写路径与操作步骤（下沉到技能 / 项目笔记）。
- 用户级文件**首行必须是规则句**；不要以 `##` 标题开头（规则层会只取标题）。
- 不加「`## 日期` 附录」堆历史：内容该并入规则就并，该下沉就下沉，该删就删。

## 反模式

- 把技能正文抄进用户级：重复成本高，技能更新后又过期。
- 把一次性决定当长期规则（例：某日「不加钱」应写进本技能的成本约束，不进用户规则）。
- 合并时两条各留一半，制造新歧义。
- 只数条数不看可执行性：10 条含糊规则不如 5 条硬规则。
- 改动前不备份、不写对照表，事后无法回滚或解释。

## 成本约束（2026-09-22「不加钱」）

本技能只用已有工具与记忆文件，不新增常驻提示、不引入额外 LLM 调用或外部服务；优化一律做减法。

## 资源清单

- 本技能没有 `references/`、`scripts/`、`templates/`：工序全部写在本文件，判据来自 `rules/` 与 DSH 记忆工具本身。

## 完成自检

- [ ] 原文有备份、路径写明
- [ ] 有对照表：N 条 → M 条（保留 / 合并 / 下沉 / 删除）
- [ ] 用户指名的置顶条目在第一条
- [ ] 下沉内容已落到技能或项目笔记；技能 `--check` 归零
- [ ] `memory_status` 字符数下降；首行是规则句
- [ ] 每条保留项都能一句话说出「漏了会怎样」
