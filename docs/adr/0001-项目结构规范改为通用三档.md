# ADR 0001 · 项目结构规范改为通用三档

- 状态：accepted
- 日期：2026-10-25

## 背景

v1 结构规范只约束准备区 `D:\lap-backstop-prep`，规则里写死了 6 个目录、3 个说明文件和准备区路径。准备区已归档，实际使用者有两类：`D:\lap-backstop` 这样的平台项目（`contracts/core/plugins/storage/tests`）与本资产仓（`rules/tools/templates/skills/evals`）。继续用一份准备区宪法，会把真实项目判成违规，或者诱导 agent 把文档与 ADR 改名搬迁。

## 决策

`rules/project-structure.md` 改为通用规范，提供三档 profile：

- A 小型项目：`docs/research/scripts/archive`；
- B 平台/应用项目：A 加 `contracts/core/plugins/storage/tests/config` 中真用到的；
- C 资产仓：`rules/tools/templates/skills/evals` 加文档与归档。

同时：根文件白名单补 `.gitattributes`、`.importlinter`；隐藏目录补 `.research/`、`.import_linter_cache/`；ADR 与文档文件名允许中文，要求同一项目统一；版本历史移入 `CHANGELOG.md`。本仓库按 Profile C 补根 `AGENTS.md`、`evals/` 与 `docs/adr/`。

## 备选

| 方案 | 不选的原因 |
|---|---|
| 保留准备区宪法，另写项目版 | 两份真源，冲突时仍要人工判断，违背「唯一真源」 |
| 只保留平台项目一档 | 资产仓没有运行时代码，`core/contracts` 对它无意义，规则会空转 |
| 不写 ADR、直接改规则 | 结构规则自己绕过 ADR 流程，后续没人知道为什么改成三档 |

## 后果

- 新项目先选 profile，再建目录；升级 profile 走 ADR。
- 仓库根多了 `AGENTS.md`、`docs/adr/`、`evals/` 三个顶层项，均由本 ADR 一次性登记。
- 结构检查仍由项目自建；本仓库只提供交付物检查与技能安装器。
