# ADR 0002 · MIT 许可证与根文件白名单

- 状态：accepted
- 日期：2026-11-02

## 背景

本仓库与 `lap-backstop` 转为对外公开。公开仓库没有许可证时，默认是「保留所有权利」：别人能看，但不能合法复制、修改、分发。`rules/project-structure.md` 的根文件白名单只列了 `README.md`、`AGENTS.md`、`.gitignore` 与按需的配置/说明类文件，没有 `LICENSE`；新增根文件类型按规则要走变更流程。

## 决策

1. 两个仓库都采用 **MIT** 许可证：`LICENSE` 放仓库根，版权声明 `Copyright (c) 2026 LapStdy`。
2. `LICENSE` 进入根文件白名单：公开仓库必需，私有仓库可不放。
3. 许可证选择只写一次（`LICENSE` 文件本身）；README 只放一行链接，不复述条款正文。

## 备选

| 方案 | 不选的原因 |
|---|---|
| Apache-2.0 | 提供专利授权，但对「单人自用的规范与工具库」是多余条款；文本更长，读者要读专利与变更声明 |
| 不放许可证 | 公开仓默认保留所有权利，与「技能与规范可被复制安装」的用法冲突 |
| 双许可证 / 自定义条款 | 增加判断成本，收益为零；MIT 已覆盖本仓库的分发需求 |
| 把全文抄进 README | 同一信息两处真源，改一处就漂 |

## 后果

- GitHub 能自动识别许可证类型，仓库页显示 MIT。
- 使用者保留版权与许可声明即可复制、修改、再分发；本仓库不承担担保责任。
- 私有仓库不受影响：白名单里 `LICENSE` 是「公开仓必需」，不是所有项目的必需项。
